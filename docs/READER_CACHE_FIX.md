# Public-file reader cache correction

This patch repairs the offline Python reference viewer. The hosted TypeScript
rules, authority, MCP methods, and browser polling logic are unchanged.

## Reproduced cause

The reader used `(st_mtime_ns, st_size)` as its unchanged-file key. A same-length
rewrite that retains the timestamp can have different bytes while matching that
key. A deterministic reproduction changed public `version` from 9 to 8 and
restored the timestamp: the previous v9 snapshot remained visible with no error.
An atomic replacement and an in-place write can both trigger this class of bug.

## Correction

Every poll opens only the selected public path in binary read-only mode and
reads at most 4 MiB + 1 bytes. Oversized contents are rejected before decoding or
parsing. Exact accepted bytes, rather than metadata, determine whether JSON
parsing can be skipped; decoding remains strictly UTF-8.

Accepting changed valid content advances a separate rendering generation. This
also makes the desktop viewer redraw when the file's size and timestamp match.
Unsupported schema clears the old snapshot, accepted-content cache, and update
time. Partial JSON, missing files, and permission failures preserve the last
good snapshot with a visible error. Restoring identical valid content clears a
transient error without replacing that snapshot or inventing a newer action.

## Verification

- All 282 Python reference checks passed, including the previous 275 checks
- Seven deterministic reader regressions passed in 50 consecutive runs
- Tests cover both rewrite modes, redraw, exact-content recovery, bounded reads,
  one-time parsing of unchanged bytes, encoding, and transient failures
- TypeScript, ESLint, all 61 Site checks, and the production build passed
- Canonical TS rules and the Python engine are byte-identical to the preceding release
- All 24 illustrations regenerated byte-for-byte identically; their manifest
  records the new renderer-source hash and the five art checks passed

The renderer-source hash changes because the reader shares the renderer file;
no drawing code or illustration bytes changed. Rebuild the generated private
art modules from the updated manifest as usual. Do not manually edit the
generated modules or restore the previous provenance hash.
