# D20 新增交互：实际云桌面核验

核验时间：2026-10-06 08:33 UTC。结论：本次范围通过，未发现需要修复的 UI 问题。

## 范围与边界

- 使用真实 Linux 云桌面、Tk 原生窗口和 CUA 鼠标/键盘，不以静态 renderer 截图代替交互核验。
- 只运行 spectator.py；没有运行引擎、开始玩家游戏、读取隐藏 save、改动真实进度、启动 Codex 或发布。
- 使用 dice-fixtures/negotiating.json、accepted.json、natural20.json，它们是作者通过临时合成状态运行真实引擎后生成的公开 observation。
- 全程带 --demo。标题包含“只读观战 · 演示”，画面包含“演示数据 · 不是真实游玩”和“演示预览 · 未推进游戏”。
- 多页历史单独使用 desktop/history-layout-demo.json：复制公开骰条目并赋予“布局样例01–12”标签，仅用于布局和分页，不代表真实经营历史。
- 初始桌面清单未发现旧游戏窗口；未关闭任何既有游戏 GUI。仅关闭过本次自己启动的第一只演示窗口以切换到可刷新的公开样例副本。

## 实际验证结果

1. 还价样例：D20 为10，显示“还价中”、标价9,999→还价60、待店主决定、只剩一次议价、接受/谢绝免费与再报价1体力。
2. 点击大骰卡进入详情；显示公开计算 D20 10−1=9 / 目标79、加值说明、还价金额、行动精力与天然20规则。Esc 能关闭详情。
3. “查看骰子记录”进入骰史；历史条目保留原骰“失败”，不把失败判定改写为成交。点击记录可进入对应详情。
4. 天然20样例：明确显示20、“天然20 · 大成功”、“成交9,999星币”，现金为10,259。
5. 接受还价样例：显示“就这个价 · 成交”、60星币成交、现金320、口碑1、货架为空。旧骰仅标为“上次 D20 10 · 初次报价未达标 · 查看记录”，未误显示还价未完成或本次交易未成。
6. 12条布局样例在桌面形成3页，第一页显示12–09，点击下一页显示08–05，页码从1/3变2/3；第二页第一条详情正确对应“布局样例08”；关闭详情后点上一页回到1/3。
7. “经营事件”按钮能从骰史切回事件日志；没有触发经营动作。
8. F11进入1364×1024全屏，布局重绘正常；Esc可回到窗口状态。详情关闭与全屏返回分别核验。
9. 手动将原生窗口调整到390×860后，演示标签、骰点、还价金额、精力提示、页签和骰史均可见，没有遮挡或关键内容裁切。

## 环境说明与复现

初次终端文本输入遇到 CUA 的 AT-SPI 窗口身份匹配错误；改用同一工具支持的键盘事件后成功启动，属于自动化工具路径问题，未修改游戏代码。

直接启动示例：

    python3 spectator.py --observation dice-fixtures/negotiating.json --demo --geometry 1200x860+60+50

云桌面会先将窗口最大化。窄窗测试使用窗口菜单恢复普通窗口后，再通过鼠标调整尺寸。
