# 同一权威状态：本地合成验证

这是架构实验，不是已部署网站，也不是完整游戏移植。没有公网监听、账号接入、凭据或真实存档迁移。

## 已验证的核心

把原有 Python 官方 CLI 放进一次性的工作目录。SQLite 保存唯一权威私档、经过白名单过滤的公开画面和操作回执。每次操作在独占写事务内计算，三者一起提交；观战读取同一数据库的公开行。

- `game_action(game_id, operation_id, expected_revision, action)`：一条已选定的官方操作
- `get_state(game_id)`：只返回当前公开画面、版本、摘要及已知图片引用
- `get_receipt(game_id, operation_id)`：查找以前成功提交的同一操作
- `dispatch(...)`：测试用的内存接口，没有HTTP服务器或认证能力，不能直接暴露到网络

重复ID且请求完全相同时返回原回执；同ID不同请求拒绝。过期revision不会执行引擎。同一revision上的并发不同操作最多提交一项。操作回执和公开画面中的摘要可以直接核对，不需要另一次“上传后再读回网页”。

## 如何运行

需要现有可信的v9游戏代码和它使用的Pillow依赖。这里不下载软件、不修改游戏源文件。

```sh
STARDUST_TEST_ENGINE=/path/to/v9/engine.py PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 benchmark.py --engine /path/to/v9/engine.py
```

测试只在自动清理的临时目录创建新合成局。环境变量只是测试引擎路径，不是凭据。不提供导入真实存档的API。

## 原子性的准确边界

保证的是“一次权威提交”，不是“CLI物理执行恰好一次”。提交前崩溃后，CLI可能在同一原始私档的临时副本里重算；被丢弃的计算不得产生现实支付、消息发送等外部副作用。这个封装只适合本地模拟规则。提交后丢失响应则只重放回执。

数据库事务不能包含外部对象存储。可选图片先写入内容寻址的对象目录，只有提交后的公开引用可读取；事务失败可能留下不可见孤立文件。图片失败不阻止权威文字状态提交，界面应显示占位。对象之后丢失时返回缺图，而不是暴露其他文件。原型对PNG数量、大小和尺寸做限制，禁止未发现物品身份。

## 未证明、未实现

- 没有生产认证、角色校验、网络服务、TLS、限流或公开部署
- 没有迁移真实存档；没有证明所有版本、全部动作和原局RNG未来序列的兼容性
- 合成差分只覆盖少量官方命令，不能代替完整迁移验收
- 没有证明断电/磁盘损坏容错；进程崩溃测试依赖SQLite、文件锁、WAL和实际存储的正确实现
- 单个SQLite写事务会覆盖CLI计算时间，不是多租户高并发方案
- 图片不是数据库同事务的一部分；没有实现生产孤立对象清理或图片绘制队列
- 不修复或绕过平台审核/授权。它消除的是“本地游戏已提交而远端镜像未提交”的结构性窗口

部署选择与接口约束见 `ARCHITECTURE.md`。测试源码应保留；不打包合成存档、数据库、WAL、截图或生成图片。
